# WebUI internationalisation

The EARE WebUI supports English (`en`), French (`fr`), Spanish (`es`), Portuguese (`pt`), Italian (`it`) and Arabic (`ar`). English is the default and fallback language.

## Selecting a language

Open the current-user menu in the top-right corner and choose a language. The interface updates immediately. The selected locale is stored only as the browser preference `eare.ui.locale`; it is not written to the domain database and the translation catalogues are not stored in the database.

## Translation files

The source catalogue is `web/src/i18n/en.json`. The other catalogues have the same semantic key set and are loaded by `web/src/i18n/index.ts`. Add a semantic key to the English catalogue first, then add the same key to every locale catalogue. Run `npm test` in `web` to validate catalogue alignment.

Translate presentation chrome only: navigation, table column names, headings, labels, buttons, help text, validation messages, generic statuses and notifications. Keep API/domain values unchanged. In particular, do not translate application names, provider/source names, identities, targets, resources, comments, native permissions, access names, UUIDs, LDAP values, API paths or technical identifiers. Stable enum values remain machine values; only their displayed labels are translated.

## Arabic and RTL

Selecting Arabic sets `lang="ar"` and `dir="rtl"` on the document. Other supported locales use `dir="ltr"`. The WebUI includes RTL rules for navigation, drawers, menus, tabs, tables, forms, pagination and notifications. Directional icons are not reversed unless their meaning is directional.

## Dates and numbers

Locale-sensitive presentation may use browser `Intl` formatting. Stored API timestamps, identifiers and database values are never changed.

## Reports

Server-generated reports are outside this presentation-layer change and may remain English-only.
