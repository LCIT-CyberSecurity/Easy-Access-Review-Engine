# Reports

Reports has two deliberately separate forms:

1. the native EARE restitution workspace in the WebUI;
2. standalone HTML, PDF, CSV and JSON deliverables for download or external
   distribution.

The WebUI must not embed the standalone HTML or PDF. It is a governance screen
that reads the existing report-results and remediation APIs.

## Native restitution workspace

The page keeps the campaign selector and accepts `/reports?campaign=<id>`.
Closed campaigns are preferred when no campaign is specified. Changing the
campaign refreshes the complete workspace.

The workspace contains:

- campaign profile: name, status, dates, pilot, scope, Snapshot, Golden version
  and reviewer coverage;
- executive summary: reviewed accesses, approvals, revocations, N/A, pending,
  and observed/expected classifications;
- deterministic key observations based only on campaign data;
- separate observed-versus-expected and review-decision breakdowns;
- remediation/action-plan totals and a human-readable preview, with a link to
  the full Actions page;
- coverage and traceability evidence;
- searchable, filterable, sortable and paginated detailed results.

The page must not invent conclusions. An observation is displayed only when the
corresponding count or factual finding exists in current campaign data.

Remediation status is not collapsed into a single completion state:

```text
pending -> exported -> completed
             \-> not completed
```

`exported` means that the action was delivered for operational follow-up. Only
`completed` confirms that the correction was recorded as done. Reports do not
execute remediation.

The main report is `campaign-report.html`. It is standalone, filterable, and designed to be shared without a backend.

It includes by default:

- campaign overview;
- access review outcome;
- review decisions;
- findings requiring attention;
- detailed rows by service, access, identity, reviewer, and decision.

Additional exports are:

- `campaign-results.csv`;
- `campaign-results.json`;
- remediation exports when generated by the calling workflow.

The HTML report can be opened separately in a new browser tab or distributed
externally. It is not rendered through an iframe, object, embed, injected HTML,
or generated-PDF preview inside the EARE Reports workspace.

Report output must never expose secrets. Dynamic values are escaped and CSV output neutralizes spreadsheet formulas.
